1판 기준으로 구현된 기능(기록 데몬, uid 신원 확인, 재채점, 스코어보드, 명단 일괄 생성)은 그대로 재사용한다. 1판의 spec·plan·tasks와 코드는 [`previous/`](../../previous/README.md)에 보관했고, 2판의 설계와 작업은 [003 plan §7](../003-practice-bank/plan.md)·[003 tasks Phase F](../003-practice-bank/tasks.md)에 있다.

## 1. 배경 (Why)

원본 CMU Bomb Lab 과제에서 폭탄은 해제·폭발을 즉시 서버에 알리고(notifying bomb), 서버는 입력을 검증해 **수강생 모두가 보는 스코어보드**를 갱신한다. 학생들은 다른 사람의 진행 상황을 보며 과제를 진행한다.

이 서버의 목적은 Bomb Lab 교육을 받은 학생들이, 나중에 수업에서 같은 과제를 받았을 때 하루 안에 해제할 수 있도록 **원본 과제와 같은 환경에서 미리 연습**하게 하는 것이다. 그래서 서버 기록과 스코어보드라는 원본의 진행 방식은 그대로 두고, 대회 전용 기능은 연습에 맞게 바꾼다.

## 2. 목표 (What)

1. 학생은 연습 서버에 SSH로 접속해 **자기 계정 안에서** 폭탄을 해체한다. 서버는 운영 기간 동안 상시 열려 있다.
2. 폭발·해제는 발생 즉시 서버 DB에 기록되며, 학생이 조작하거나 남의 기록을 위조할 수 없다.
3. 웹 스코어보드에서 전체 학생의 과제형 폭탄 점수와 드릴 진도를 실시간으로 본다.
4. 학생은 개념 드릴과 연습 폭탄을 원할 때마다 새로 받을 수 있고, 해제한 단계의 해설을 볼 수 있다.
5. 운영자는 명단 파일 하나로 계정·폭탄을 일괄 준비한다.

### 성공 기준

- 30명 규모를 서버 1대로 학기 내내 무리 없이 운영한다.
- 학생은 접속 정보 카드 한 장만 받으면 바로 시작할 수 있다.
- 운영자 개입 없이 학생 스스로 드릴·연습 폭탄을 재발급받고 해설을 열람한다.

## 3. 사용자 시나리오

### S1. 학생 — 드릴
`ssh bomb07@서버`로 접속한다. `~/drills/d3/`에서 드릴을 풀고, 단계를 해제하면 `~/drills/d3/notes/`에 그 단계의 해설이 생긴다. 다시 연습하고 싶으면 재발급 명령으로 새 시드의 드릴을 받는다. 스코어보드의 드릴 진도 표에 자기 칸이 채워진다.

### S2. 학생 — 과제형 폭탄
`~/bomb/`의 과제형 폭탄을 원본 과제처럼 푼다. 해제·폭발할 때마다 스코어보드의 점수가 바뀐다. 실력을 더 다지고 싶으면 연습 폭탄을 새로 받아 점수 부담 없이 반복한다.

### S3. 운영자 — 준비와 운영
Ubuntu 서버에 저장소를 받아 설치 스크립트를 실행한다. 설정 파일에 운영 기간(선택)과 채점 규칙을 적는다. 명단 CSV로 계정, 과제형 폭탄, 드릴 세트를 일괄 생성하고 접속 정보 카드를 나눠 준다. 관리자 화면에서 학생별 이벤트와 입력 원문을 본다. 운영 기간이 끝나면 결과를 CSV로 내보낸다.

## 4. 기능 요구사항 (FR)

### 4.1 기록과 신원 (1판 유지)

| ID | 요구사항 |
|---|---|
| FR-01 | 서버 모드 폭탄은 phase 시작 전에 기록 서버에 접속을 확인하고, 실패하거나 운영 기간이 아니면 사유를 알리고 phase를 시작하지 않는다. |
| FR-02 | 폭발과 해제는 발생 즉시 폭탄 ID, phase(단계) 번호, 입력 원문을 포함해 서버에 보고된다. secret phase 포함. |
| FR-03 | 서버는 보고한 프로세스의 **운영체제 사용자**로 학생을 식별한다. 폭탄 파일이나 메시지 내용으로 신원을 판단하지 않는다. 보고된 폭탄 ID가 그 사용자에게 발급된 것이 아니면 거부한다. |
| FR-04 | 서버는 해제 보고의 입력을 그 폭탄의 판정 규칙으로 **다시 채점**하고, 통과할 때만 해제로 인정한다. 정답 목록 비교가 아니라 판정 로직 재실행이므로 정답이 여러 개인 phase도 처리한다. 채점에 실패한 해제 보고는 폭발 1회로 계산한다. |
| FR-05 | 서버 응답은 해제 보고의 유효 여부를 드러내지 않는다. |
| FR-06 | 학생별 보고 빈도를 제한한다(기본 분당 60건). |

### 4.2 폭탄 트랙

| ID | 요구사항 |
|---|---|
| FR-10 | 서버는 폭탄마다 트랙을 기록한다: **과제형**(학생당 1개, 점수 반영), **연습**(재발급 가능, 점수 미반영), **드릴**(드릴 번호별, 재발급 가능, 점수 미반영). |
| FR-11 | 학생은 서버 계정 안에서 명령 하나로 연습 폭탄 또는 특정 드릴을 새 시드로 재발급받는다. 빌드는 학생 권한이 아니라 서버가 수행하며, 학생은 생성기·시드에 접근하지 않는다. |
| FR-12 | 재발급 시 이전 폭탄은 비활성화되어 더 이상 기록되지 않는다. 이전 기록은 DB에 남는다. |
| FR-13 | 과제형 폭탄은 학생 요청으로 재발급되지 않는다(원본 과제와 같이 1인 1폭탄). 운영자 명령으로만 재발급한다. |

### 4.3 해설 공개

| ID | 요구사항 |
|---|---|
| FR-20 | 드릴·연습 폭탄의 단계가 유효하게 해제되면, 서버가 그 단계의 해설을 학생 홈의 해당 폭탄 디렉터리에 설치한다. |
| FR-21 | 과제형 폭탄은 해설과 힌트를 **공개하지 않는다**(실제 과제와 같은 조건). |
| FR-22 | 드릴·연습 폭탄의 각 단계에는 3단계 힌트가 있다. 시간 제한 없이 학생이 요청하면 열리며, 1 → 2 → 3 순서로만 열린다. |

### 4.4 스코어보드

| ID | 요구사항 |
|---|---|
| FR-30 | 공개 스코어보드는 **과제형 폭탄** 기준으로 닉네임·phase별 해제 여부와 시각·폭발 수·점수·순위를 보여주며 자동 갱신된다. 원본 과제의 스코어보드와 같은 구성이다. |
| FR-31 | 공개 스코어보드는 별도 표로 학생별 **드릴 진도**(드릴 × 3단계 해제 현황)와 연습 폭탄 완주 횟수를 보여준다. 이 표는 순위·점수에 영향을 주지 않는다. |
| FR-32 | 공개 기록 피드는 닉네임·트랙·phase·시각만 보여주고 **입력 원문은 보여주지 않는다**. |
| FR-33 | 관리자 화면은 인증 후에만 접근 가능하며, 학생별 전체 이벤트(모든 트랙)와 입력 원문을 보여준다. |
| FR-34 | 채점 규칙은 설정 파일로 정한다. 기본값은 원본 과제 안내문 기준: phase 1~4 각 10점, phase 5~6 각 15점(합 70점), 폭발 -0.5점, 감점 상한 20점. secret 10점. 폭발 감점은 과제형 폭탄에만 적용한다. |

### 4.5 운영

| ID | 요구사항 |
|---|---|
| FR-40 | 운영 기간(시작·종료)을 설정한다. 기본 운영은 교육 직후부터 수업 과제가 나오기 전까지 **2주**다. 운영 기간 밖에서는 로그인과 기록이 차단된다. 설정하지 않으면 상시 열려 있다. |
| FR-41 | 명단 CSV 한 번으로 학생 계정, 무작위 비밀번호, 과제형 폭탄, 드릴 세트, 인쇄용 접속 정보 카드를 생성한다. 이미 존재하는 학생은 건너뛴다. 운영 중 학생 추가가 가능하다. |
| FR-42 | 운영자는 비밀번호 재발급, 과제형 폭탄 재발급, 상태 조회, 결과 내보내기를 명령으로 수행한다. |
| FR-43 | 오프라인 모드(로컬 로그) 빌드는 운영자 테스트용으로 유지된다. |

## 5. 비기능 요구사항 (NFR)

| ID | 요구사항 |
|---|---|
| NFR-01 **위조 불가** | 학생은 다른 학생 명의로 기록을 남길 수 없고, 정답을 모르는 채 해제 기록을 얻을 수 없다. |
| NFR-02 **정답 비노출** | 학생 폭탄에는 시드가 들어가지 않는다. 생성기 소스, 시드, 기록 DB, 아직 열리지 않은 해설, 다른 학생의 파일·프로세스는 학생 계정에서 읽을 수 없다. |
| NFR-03 **채점 일치** | 서버의 재채점 결과는 폭탄 바이너리의 판정과 경계 입력을 포함해 **항상 일치**한다. 모든 변형 계열·드릴 단계에 대해 자동 검증한다(003 NFR-10). |
| NFR-04 **자원 공정성** | 학생 한 명이 CPU·메모리·프로세스를 독점해 다른 학생을 방해할 수 없다. 재발급 빌드도 동시 실행 수를 제한한다. |
| NFR-05 **가용성** | 기록·웹 서비스는 비정상 종료 시 자동 재시작된다. 기록 서버가 잠시 불통이어도 해제 기록이 유실되지 않는다(폭탄이 해제 보고 실패 시 멈추고 재실행을 안내). |
| NFR-06 **장기 운영** | 학기 단위 운영을 전제로 DB 백업과 로그 순환을 제공한다. |
| NFR-07 **의존성 최소화** | 서버 구성요소는 Ubuntu 기본 패키지와 Python 표준 라이브러리만 사용한다. |
| NFR-08 **이식성** | Ubuntu 22.04와 24.04에서 설치 스크립트 하나로 동작한다. 클라우드 VM과 학교 서버 모두 지원한다. |
| NFR-09 **무권한 검증** | 서버 핵심 동작은 root 권한 없이 로컬(WSL)에서 자동 검증할 수 있다. |

## 6. 수용 기준 (Acceptance Criteria)

- **AC-01** 과제형 폭탄 정답 파일 실행 시 해제 6건이 기록되고 스코어보드 점수가 70점이다(기본 채점 규칙).
- **AC-02** 오답으로 과제형 폭탄이 폭발하면 폭발 1건과 -0.5점이 반영된다. 드릴·연습 폭탄의 폭발은 점수에 반영되지 않는다.
- **AC-03** 소켓에 직접 접속해 틀린 입력으로 해제를 주장하면 `invalid`로 기록되어 폭발로 계산되고, 응답은 정상 기록과 구별되지 않는다.
- **AC-04** 다른 학생의 폭탄 ID, 또는 재발급으로 비활성화된 자기 폭탄 ID로 보고하면 거부된다.
- **AC-05** 학생이 드릴 재발급 명령을 실행하면 새 시드의 드릴이 설치되고, 이전 드릴의 보고는 거부된다. 과제형 폭탄은 학생 명령으로 재발급되지 않는다.
- **AC-06** 드릴 단계를 해제하면 그 단계의 해설만 학생 홈에 설치되고, 다른 단계 해설은 읽을 수 없다.
- **AC-07** 스코어보드에 과제형 점수표와 드릴 진도표가 따로 표시되고, 드릴 진도는 순위에 영향을 주지 않는다.
- **AC-08** 운영 기간을 설정하지 않으면 언제든 접속·기록된다. 설정하면 기간 밖의 로그인과 폭탄 실행이 거부된다.
- **AC-09** 보고 빈도 한도를 넘으면 거부되고 기록된다.
- **AC-10** 인증 없이 관리자 화면에 접근하면 401을 받는다.
- **AC-11** 모든 변형 계열·드릴 단계에서 경계 입력 퍼징 결과 서버 채점과 폭탄 판정이 일치한다.
- **AC-12** 학생 계정에서 다른 학생 홈, 생성기 저장소, 기록 DB, 열리지 않은 해설을 읽을 수 없고, 다른 학생의 프로세스가 보이지 않으며, SSH 포트 포워딩이 거부된다.

AC-01~11은 root 없이 자동 검증한다. AC-12와 AC-08의 로그인 부분은 실서버 리허설로 검증한다.

## 7. 범위 밖 (Out of Scope)

- 학생의 AI 사용·외부 검색 차단 — 연습 서버이므로 강제하지 않는다. 학습 효과를 위해 자제를 권고만 한다.
- 대회 운영 기능(프리즈, 시작 시각 동시 개방).
- 다중 서버·로드밸런싱.
- 웹에서의 학생 자가 가입.
- gdb로 폭발을 피하는 행위의 차단 — 이 랩의 정석 기법이다.
- CMU 원본 바이너리의 서버 배포(003 §7).
