# Spec: 대회용 신규 Bomb Lab

- **Feature ID**: 001-new-bomb
- **Status**: Draft
- **작성일**: 2026-09-08

---

## 1. 배경 (Why)

CMU Bomb Lab은 x86-64 어셈블리 리버싱을 가르치는 검증된 과제다. 그러나 원본 phase 1~6의 정답과 풀이는 인터넷과 학내 족보로 광범위하게 유출되어 있어, 그대로 대회에 사용하면 **문제 해결 능력이 아니라 자료 보유 여부를 측정**하게 된다.

원본이 주는 학습 경험 — 바이너리만 주어진 상태에서 objdump로 흐름을 읽고, gdb로 메모리를 관찰하고, 역산해서 입력을 알아내는 과정 — 은 그대로 유지하되, **문제 자체는 처음 보는 것**이어야 한다.

## 2. 목표 (What)

1. 원본과 무관한 새로운 7개 phase(6 + secret)로 구성된 폭탄을 제작한다.
2. 참가자마다 상수가 다른 변형을 생성해 답 공유를 억제한다.
3. 대회 운영에 필요한 문서(참가자 안내, 개념 교육자료, 출제자 해설서)를 함께 제공한다.

### 성공 기준

- 원본 Bomb Lab 풀이를 그대로 알고 있어도 이 폭탄에는 **어떤 이점도 없다**.
- 시스템프로그래밍 수강 수준의 참가자가 4~6시간 안에 6 phase를 해제할 수 있다.
- 모든 phase가 **손계산으로 역산 가능**하며, 스크립트 없이 종이와 펜으로 풀린다.

## 3. 사용자 시나리오

### S1. 참가자
바이너리 `bomb`과 배포용 `bomb.c`, 안내 문서만 받는다. `objdump -d bomb`로 전체 흐름을 파악하고, gdb로 각 phase에 브레이크포인트를 걸어 메모리·레지스터를 관찰하며 입력을 역산한다. 알아낸 답을 파일에 한 줄씩 적고 `./bomb sol.txt`로 검증한다. 틀리면 폭발하고 프로세스가 종료되므로, 새 phase는 반드시 gdb 안에서 먼저 시험한다.

### S2. 출제자
시드 번호를 지정해 폭탄을 생성한다. 생성기는 상수와 테이블을 시드로 결정하고, 각 phase의 정답이 유일한지 검증한 뒤 정답 파일과 해설서를 함께 출력한다. 검증 스크립트로 전 시드가 정상인지 확인한 후 배포 패키지를 만든다.

### S3. 진행요원
대회 중 막힌 참가자에게 해설서의 3단계 힌트를 순서대로 지급한다. 종료 후 각 참가자의 `bomb.log`를 수거해 해제 phase 수와 폭발 횟수로 순위를 매긴다.

## 4. 기능 요구사항 (FR)

| ID | 요구사항 |
|---|---|
| FR-01 | 폭탄은 6개의 공개 phase와 1개의 secret phase를 가진다. |
| FR-02 | 입력은 인자 없이 실행 시 stdin, 파일 경로를 주면 그 파일에서 한 줄씩 읽는다. |
| FR-03 | 오답 입력 시 `BOOM!!!`을 출력하고 **즉시 프로세스를 종료**한다. |
| FR-04 | 폭발과 해제 모두 `bomb.log`에 `시각 / 시드 / phase 번호 / 결과` 형식으로 append 기록한다. |
| FR-05 | secret phase는 존재를 공지하지 않으며, 특정 phase의 정답 줄 뒤에 숨은 토큰을 덧붙인 참가자만 6 phase 해제 후 진입한다. |
| FR-06 | 시드를 바꾸면 모든 phase의 상수·테이블·정답이 달라진다. **로직 구조는 시드와 무관하게 고정**된다. |
| FR-07 | 바이너리는 심볼을 유지하고 `-O1 -no-pie`로 빌드해 원본 Bomb Lab과 유사한 가독성을 갖는다. |
| FR-08 | 배포 패키지에는 바이너리, 배포용 `bomb.c`, 참가자 문서만 포함한다. 비공개 소스(`phases.c`)·정답 파일·해설서는 **절대 포함되지 않는다**. |
| FR-09 | 생성기는 시드마다 정답 파일과 출제자 해설서를 자동 생성한다. |
| FR-10 | 검증 스크립트는 다수 시드에 대해 정답 통과·오답 폭발·유일해를 자동 확인하고, 하나라도 실패하면 비영으로 종료해 배포를 차단한다. |

## 5. 비기능 요구사항 (NFR)

| ID | 요구사항 |
|---|---|
| NFR-01 **유일해** | 각 phase의 정답은 정확히 하나다. 전수 조사가 가능한 phase는 전수로, 불가능한 phase는 수학적 근거(전단사·결정적 점화식·소수 모듈러)로 보장한다. |
| NFR-02 **노가다 금지** | 정답에 도달하는 데 필요한 반복 손계산은 phase당 **6스텝 이하**다. 순열 전수 탐색(720가지 등), 64개 이상의 경우의 수 시도, 긴 테이블 암기를 요구하지 않는다. |
| NFR-03 **덤프 분량** | 참가자가 읽어야 하는 메모리 테이블은 phase당 **16바이트 이하** 또는 경로상 방문 노드로 한정된다. |
| NFR-04 **난이도 곡선** | phase 1~2는 objdump만으로, 3~4는 gdb 관찰이 필요하게, 5~6은 자료구조 순회와 비트연산 결합으로 설계한다. |
| NFR-05 **시드 균일성** | 시드가 달라도 체감 난이도가 유의미하게 달라지지 않는다. 생성기가 퇴화 케이스(자명한 상수, 조기 수렴)를 배제한다. |
| NFR-06 **소재 제한** | 모든 phase는 비트연산·정수론 또는 자료구조 순회 계열이다. 원본의 문자열 비교/등차수열/switch/재귀/문자 매핑/연결리스트 정렬 조합은 사용하지 않는다. |
| NFR-07 **결정성** | 동일 시드는 항상 동일한 바이너리와 정답을 만든다. |

## 6. 수용 기준 (Acceptance Criteria)

- **AC-01** 임의 시드로 빌드한 폭탄에 해당 시드의 정답 파일을 주입하면 6 phase가 모두 해제되고 종료 코드가 0이다.
- **AC-02** 정답 줄에 secret 토큰을 덧붙이면 secret phase까지 해제된다.
- **AC-03** 각 phase에 대해 경계값·off-by-one·형식 오류 오답을 주입하면 **정확히 그 phase에서** 폭발하고 종료 코드가 0이 아니다.
- **AC-04** phase 3과 secret phase는 입력 공간 전수 실행 결과 정답이 정확히 1개다.
- **AC-05** 서로 다른 시드 20개에 대해 AC-01~04가 모두 통과한다.
- **AC-06** 배포 패키지 디렉터리에 `phases.c`, `solution.txt`, `SOLUTION.md`, `bombdata.h`가 존재하지 않는다.
- **AC-07** 폭발·해제 후 `bomb.log`에 해당 이벤트가 기록된다.
- **AC-08** 출제자가 생성기의 정답을 보지 않고 직접 풀었을 때, 목표 소요 시간(6 phase 4~6시간) 범위 안에 든다.

## 7. 범위 밖 (Out of Scope)

- 안티디버깅(ptrace 탐지, 타이밍 체크) 및 코드 난독화 — 참가자의 gdb 학습을 방해하므로 채택하지 않는다. AI 사용은 대회 규칙과 감독으로 통제한다.
- 온라인 채점 서버·자동 제출 시스템 — 로컬 로그 수거로 대신한다.
- Windows 네이티브(PE) 빌드, 32비트 빌드.
- 참가자 실행 환경(서버 계정/WSL/USB) 배포 인프라 구축 — 대회 운영 결정 사항.

## 8. 미해결 사항

- 참가자 Linux 실행 환경 제공 방식이 확정되면 참가자 README에 반영한다.
