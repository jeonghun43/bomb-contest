- **Feature ID**: 003-practice-bank
- **Status**: Draft

- **대체**: [001-new-bomb](../../previous/specs/001-new-bomb/spec.md) (대회용 자체제작 폭탄 — 폐기, `previous/`에 보관)

## 1. 배경 (Why)

001은 **대회**를 전제로, 원본 풀이가 통하지 않는 자체제작 폭탄을 만들었다. 대회는 열지 않기로 했고 목적이 바뀌었다.

> Bomb Lab 교육 이후 서버를 상시 열어 두고, 학생들이 시스템프로그래밍 수업에서 Bomb Lab 과제를 받았을 때 **하루 안에 전부 해제할 수 있는 실력**을 미리 기른다.

이 목적에서는 "원본과 달라야 한다"가 아니라 **"원본과 최대한 같아야 한다"** 가 기준이다. 과제에서 만날 코드 패턴·빌드 환경·판정 방식·채점 방식에 미리 익숙해져야 실력이 그대로 옮겨 간다. 동시에 과제 폭탄은 학기·교수자마다 변형이 다르므로, 풀이 하나를 외우는 것이 아니라 **패턴을 보는 즉시 알아보는 능력**을 길러야 한다.

001의 자체제작 phase(회전·XOR, LFSR, 토러스, 모듈러 역원, 트리 경로, 마스크 사슬)는 문제은행에서 제외한다. 일부 아이디어는 개념 드릴의 응용 단계 소재로 재사용할 수 있다(§9).

## 2. 목표 (What)

1. 문제은행은 두 트랙으로만 구성한다.
   - **개념 드릴(Lv.1)**: 원본 Bomb Lab에 나오는 개념 하나씩을 집중 연습하는 미니 폭탄.
   - **CMU 구조 폭탄(Lv.2)**: 원본과 같은 구조의 6+1 phase 폭탄. 상수·테이블·정답만 시드마다 다르다.
2. 폭탄의 빌드 환경, 입력 처리, 판정 방식, 서버 보고, 채점을 **원본 과제와 최대한 같게** 맞춘다.
3. 참가자끼리 서로의 점수를 볼 수 있는 스코어보드 구조를 유지한다(002).

### 성공 기준

- 개념 드릴을 모두 마친 학생은 CMU 구조 폭탄을 **처음 받은 날 하루 안에** 6 phase를 해제한다.
- 원본의 phase 계열 중 어느 변형을 받아도, 학생이 "이건 처음 보는 구조"라고 느끼는 phase가 없다.
- 원본과 **같은 컴파일러·같은 플래그**로 빌드해, 원본 바이너리와 우리 폭탄을 `objdump -d`로 나란히 놓았을 때 상수·주소 말고는 차이가 없다(함수 구성, 호출 관례, 카나리 위치, 디버그 정보 범위, 명령어 관용구).

### 원칙: 원본과 무조건 같게

컴파일러·빌드 환경에서 비롯되는 차이는 연습 대상이 아니다. 모든 폭탄(드릴 포함)은 원본과 같은 툴체인과 플래그로만 빌드한다. "다른 컴파일러나 다른 최적화 수준에서는 이렇게 보인다" 같은 문제는 만들지 않는다. 원본 환경 실측 결과는 [research.md](research.md)에 있다.

## 3. 사용자 시나리오

### S1. 학생 — 교육 직후
SSH로 연습 서버에 접속한다. `~/drills/`에 개념 드릴이 있다. D0(도구)부터 차례로 푼다. 단계를 해제하면 그 단계의 해설이 열린다. 막히면 시간이 지나며 힌트가 하나씩 열린다. 드릴은 몇 번이든 새 시드로 다시 받을 수 있고, 폭발해도 감점이 없다.

### S2. 학생 — 실전 연습
드릴을 마치면 `~/bomb/`의 **과제형 폭탄**에 도전한다. 원본 과제처럼 학생마다 하나씩 배정되고, 폭발은 감점되며, 결과가 스코어보드에 올라간다. 과제형 폭탄과 별도로 **연습 폭탄**(같은 CMU 구조, 점수 없음)을 원할 때마다 새로 받아 반복 연습할 수 있다.

### S3. 출제자
생성기에 트랙·드릴 번호·시드를 주면 폭탄, 정답, 해설서가 만들어진다. 검증 스크립트가 모든 변형 계열을 빠짐없이 빌드·실행해 정답 통과, 오답 폭발, 서버 재채점 일치를 확인한다.

### 4.2 CMU 구조 폭탄 (Lv.2)

| ID | 요구사항 |
|---|---|
| FR-10 | phase 1~6과 secret phase의 **구조는 원본과 같다**. 각 phase는 원본에서 알려진 변형 계열 중 하나를 시드로 고르고, 그 안의 상수·테이블·문자열을 시드로 정한다(§8). |
| FR-11 | 함수·전역 심볼의 이름과 구성은 원본 관례를 따른다(`phase_N`, `read_six_numbers`, `strings_not_equal`, `string_length`, `func4`, `fun7`, `node1`…, `phase_defused`, `explode_bomb` 등). |
| FR-12 | 판정 방식은 원본과 같다. 각 phase는 원본과 **같은 순서로 같은 지점에서** 조건을 검사하고, 실패하는 즉시 폭발한다. 원본이 원소별로 검사하면 원소별로, 마지막에 한 번 비교하면 마지막에 한 번 비교한다. |
| FR-13 | secret phase 진입은 원본과 같은 방식이다(phase 4 답 줄 뒤의 추가 문자열을 `phase_defused`가 다시 읽음). 진입 문자열은 시드로 정한다. |
| FR-14 | 학생은 **과제형 폭탄** 1개를 배정받는다(점수 반영). 별도로 **연습 폭탄**을 원할 때마다 새 시드로 받을 수 있다(점수 미반영). |

### 4.3 개념 드릴 (Lv.1)

| ID | 요구사항 |
|---|---|
| FR-20 | 드릴은 개념 하나에 집중한 미니 폭탄이며, **3단계(기본 → 변형 → 응용)** 로 구성된다(§9). |
| FR-21 | 각 드릴은 CMU 구조 폭탄의 어느 phase를 대비하는지 명시한다. 모든 원본 phase 계열은 최소 하나의 드릴로 대비된다. |
| FR-22 | 응용 단계는 앞 드릴의 개념과 결합하거나 원본에 없는 변형 형태를 써서, 과제에서 처음 보는 응용 문제에 대응하는 연습이 되게 한다. |
| FR-23 | 드릴은 폭발해도 감점이 없고, 학생이 원할 때 새 시드로 다시 받을 수 있다. |
| FR-24 | 단계를 해제하면 그 단계의 해설(핵심 패턴, 원본 과제에서 이 패턴이 나오는 모습)이 학생에게 열린다. |
| FR-25 | 드릴 진도(드릴별 단계 해제 현황)는 스코어보드에 과제형 폭탄 점수와 **별도로** 표시된다. |

### 4.4 입력 처리 (원본과 동일하게)

| ID | 요구사항 |
|---|---|
| FR-30 | 인자 없이 실행하면 stdin, 파일 인자를 주면 그 파일에서 한 줄씩 읽는다. **파일이 끝나면 stdin으로 이어서 읽는다.** stdin이 끝나면 `Error: Premature EOF on stdin` 후 종료 코드 8. (research §3) |
| FR-31 | 한 줄은 `fgets(…, 80, …)`로 읽고 빈 줄은 건너뛴다. 78자를 넘으면 `Error: Input line too long` 후 폭발한다. 입력 줄은 80바이트 × 20줄 배열에 보관한다. |
| FR-32 | `SIGINT` 처리기는 원본과 같은 순서로 동작한다(메시지 → 3초 → 메시지 → 1초 → 메시지 → 종료 코드 16). |
| FR-33 | 시작·단계 해제·secret·폭발 메시지와 출력 함수(`puts`/`printf`)의 사용은 원본과 같다. 배포용 `bomb.c`는 직접 작성하되, 코드 구조와 `main`의 흐름은 원본 배포본과 같다. |
| FR-34 | secret phase 입력은 원본처럼 `read_line` 후 `strtol(…, NULL, 10)`로 읽는다. |
| FR-35 | 서버 보고 코드는 원본 과제용 버전처럼 `explode_bomb`·`phase_defused` 안에서 호출된다. 보고 방식(유닉스 소켓)은 원본(HTTP)과 다르며, 이것이 원본과 다른 유일한 동작 차이다. |

## 6. 수용 기준 (Acceptance Criteria)

- **AC-01** 모든 변형 계열에 대해, 시드의 정답 파일을 넣으면 6 phase가 해제되고 종료 코드가 0이다. secret 진입 문자열을 덧붙이면 secret까지 해제된다.
- **AC-02** 모든 드릴 단계에 대해 정답은 통과하고, 경계값·형식 오류 오답은 **정확히 그 단계에서** 폭발한다.
- **AC-03** 퍼징 결과, 모든 변형 계열·드릴 단계에서 서버 재채점과 폭탄 판정이 일치한다.
- **AC-04** 배포 바이너리에서 phase 코드의 DWARF 정보(지역변수·구조체 필드·소스 경로)가 발견되지 않는다.
- **AC-05 (툴체인 보정)** 원본 자습용 폭탄의 phase 1~6, `func4`, `fun7`, `secret_phase`, `phase_defused`, `read_line`, `strings_not_equal`을 직접 C로 재구성해 우리 툴체인으로 빌드하면, 원본과 **명령어 단위로 일치**한다(주소·상수 차이만 허용). 이 보정 빌드는 원본 정답이 들어가므로 학생에게 배포하지 않는다.
- **AC-05b** 배포 폭탄은 원본과 같이 non-PIE, strip 안 함, DWARF는 `bomb.c` 하나, 카나리는 원본과 같은 함수에만 있고, `endbr64`가 없다.
- **AC-06** 정답 파일이 3단계까지만 있을 때 `./bomb ans.txt`를 실행하면 3단계를 해제한 뒤 stdin에서 4단계 입력을 기다린다.
- **AC-07** 배포 패키지에 비공개 소스, 정답, 해설서, 생성 데이터 파일이 없다.
- **AC-08** 파일럿: 드릴을 마친 학생 3명 이상이 처음 받은 CMU 구조 폭탄을 하루(8시간) 안에 6 phase 해제한다.

## 7. 범위 밖 (Out of Scope)

- 001의 자체제작 phase를 문제은행에 포함하는 것.
- 대회 운영 기능(시작·종료 시각에 따른 접속 차단, 리더보드 프리즈) — 002 개정에서 제거.
- 안티디버깅, 코드 난독화.
- CMU 원본 바이너리나 소스의 재배포. 원본 자습용 폭탄은 학생이 공식 사이트에서 직접 받도록 **안내만** 한다. 서버의 폭탄은 모두 직접 작성한 코드로 만든다.

## 8. CMU 구조 폭탄 — phase별 변형 계열

원본은 학기·버전마다 phase 안의 변형이 다르다. 굵게 표시한 계열은 자습용 배포본에서 **실측한 구조**다(research §3). 나머지는 다른 학기 버전에서 알려진 계열로, 구현 전 공개 자료로 확인해 확정한다. 모든 계열은 같은 툴체인으로 빌드하므로, 계열 사이의 차이는 **소스 수준의 문제 구조 차이**뿐이다.

| phase | 다루는 개념 | 변형 계열 (시드로 선택) | 시드로 바뀌는 것 |
|---|---|---|---|
| 1 | 문자열 비교 | **`strings_not_equal`로 전역 문자열과 비교** | 문장 |
| 2 | 반복문, 배열 | 6개 수열: **2배 수열** / `a[i]=a[i-1]+i` / `a[i]=a[i-1]*(i+1)` 등 | 초항, 점화식 계수 |
| 3 | switch, 점프 테이블 | **`"%d %d"` 점프 테이블(case 0~7)** / `"%d %c %d"` 점프 테이블 | case별 상수, 유효 case 수 |
| 4 | 재귀 | **`func4(x, 0, 14)` 이진 탐색형** / 피보나치형 재귀 | 탐색 범위, 목표 반환값, 둘째 수 |
| 5 | 문자 처리, 배열 인덱싱 | **글자 `& 0xf`로 16칸 표 인덱싱 → 목표 단어** / `"%d %d"` 배열 순환(다음 인덱스 따라가기, 횟수·합 검사) | 16칸 표, 목표 문자열, 순환 배열 |
| 6 | 구조체, 연결 리스트 | **1~6 순열 → `7-x` → 노드 재배열 → 내림차순** / 변환 없음·오름차순 조합 | 노드 값, 정렬 방향, 변환 여부 |
| secret | 이진 트리, 재귀 | **`strtol` → 범위 1~1001 → `fun7` BST 경로 인코딩** | 트리 값, 목표 반환값, 진입 문자열 |

## 9. 개념 드릴 구성

각 드릴은 **3단계 미니 폭탄**이다. 모든 드릴은 원본과 같은 툴체인·플래그로 빌드한다(§2 원칙).

- ① **기본**: 원본 phase에 나오는 패턴을 가장 단순한 문제로 보여 준다.
- ② **변형**: 같은 개념을 **원본의 다른 변형 계열**(§8)이나 다른 입력 형식으로 낸다. 같은 컴파일러가 소스 구조 차이 때문에 다르게 만드는 코드(예: 밀집 switch와 희소 switch)는 포함하지만, 컴파일러·최적화 수준을 바꿔서 생기는 차이는 다루지 않는다.
- ③ **응용**: 앞 드릴의 개념과 결합하거나 조건을 하나 더 얹어, 과제에서 처음 보는 응용 문제에 대비한다.

**분량 원칙 (2026-10-06)**: 드릴 단계는 **그 개념만** 보이게 짧게 만든다(명령어 8~44개, 정렬용 `nop` 제외). 과제 phase에 붙는 부수적인 검사(두 번째 입력값, 중복 검사, 재연결 등)는 드릴에서 빼고, 해설의 "과제에서는"에 무엇이 더 붙는지 적는다. 원본과 똑같은 전체 모양은 CMU 구조 연습 폭탄이 맡는다. 점프 테이블처럼 컴파일러가 만드는 구조 자체가 학습 대상인 경우, 그 구조가 나오는 최소 크기는 지킨다(GCC 4.8은 case 5개부터 점프 테이블).

| 드릴 | 개념 | ① 기본 | ② 변형 | ③ 응용 | 대비 phase |
|---|---|---|---|---|---|
| **D0** | 도구 기본기 | 답이 `.rodata`에 그대로 있음 (`x/s`) | 비교하는 값이 `cmp` 직전 레지스터에만 있음 (`info registers`) | 답이 실행 중 전역 버퍼에 만들어짐 (`strings`로 안 보임, `x/s $rsi`) | 전체 |
| **D1** | 문자열 | `strings_not_equal`로 전역 문자열 비교 | 길이를 먼저 검사한 뒤 비교, 문자열이 `movabs` 즉시값으로 스택에 조립됨(리틀 엔디언, 카나리) | 입력 길이로 문자열 포인터 배열 중 하나를 골라 비교 | 1 |
| **D2** | 산술·비교 | `lea`/`imul`/시프트로 만든 식 = 상수 | 같은 수를 부호 없는(`jb`)·부호 있는(`jg`) 비교로 한 번씩 | 부호 없는 상수 나눗셈(매직 넘버)과 나머지 | 2·4 |
| **D3** | 반복문·배열 | `read_six_numbers` + 2배 수열 | 원본의 다른 점화식 계열 (`a[i-1]+i`, `a[i-1]*(i+1)`) | 홀짝에 따라 바뀌는 수열, 앞의 두 값을 쓰는 수열 | 2 |
| **D4** | switch·점프 테이블 | 밀집 switch(case 5개), 테이블을 `x/5gx`로 읽기 | `"%d %c"` 형식, case 범위 오프셋(`sub` 후 `ja`) | 희소 switch(키 4개, 비교문), fall-through | 3 |
| **D5** | 함수 호출·재귀 | 인자 3개 보조 함수 (`%rdi`,`%rsi`,`%rdx`) | `func4` 이진 탐색형 재귀 (입력 1개) | 재귀 호출이 2번인 함수, callee-saved 레지스터 | 4 |
| **D6** | 문자 처리·테이블 | 글자 `& 0xf`로 16칸 표 인덱싱 → 목표 글자와 하나씩 비교 | 글자로 고른 int 표 값의 합 = 목표 | 배열 순환: 다음 인덱스를 따라가며 횟수 검사 (거꾸로 추적) | 5 |
| **D7** | 구조체·연결 리스트 | 노드 따라가며 값 찾기 (`x/24wx`) | 번호로 노드 고르기 → 고른 값이 오름차순 | phase 6의 핵심: `7-x`로 노드 고르기 → 내림차순 (중복 검사·포인터 배열·재연결은 연습 폭탄에서) | 6 |
| **D8** | 이진 트리 | 반복문으로 BST 탐색, 깊이 = 목표 | `fun7` 경로 인코딩으로 목표 반환값 만들기 | 반복문으로 경로 합 = 목표 (트리 덤프·추적) | secret |
| **D9** | 숨은 단계·전체 흐름 | 몸풀기 | 숨은 단계 토큰을 싣는 줄 (`sscanf`가 나머지를 무시) | 전역 변수(`num_input_strings`)에 달린 답 + 숨은 단계 진입 | secret 진입 |

- 총 10개 드릴 × 3단계 = 30단계(+ D9 숨은 단계). D0 → D9 순서를 권장하되 강제하지 않는다.
