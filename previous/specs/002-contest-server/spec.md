# Spec: 대회 서버 (SSH 해체 + 서버 기록 + 리더보드)

- **Feature ID**: 002-contest-server
- **Status**: Draft
- **작성일**: 2026-09-11
- **선행**: [001-new-bomb](../001-new-bomb/spec.md)

---

## 1. 배경 (Why)

001에서 만든 폭탄은 결과를 참가자 홈 디렉터리의 `bomb.log`에만 남긴다. 이 방식에는 세 가지 문제가 있다.

1. **신뢰할 수 없다.** 참가자가 로그를 지우거나 고칠 수 있다.
2. **실시간이 아니다.** 운영자는 대회가 끝난 뒤에야 로그를 수거해 순위를 매길 수 있다.
3. **대회 분위기가 없다.** 참가자는 다른 사람의 진행 상황을 볼 수 없다.

CMU Bomb Lab은 폭탄이 결과를 서버에 알리고(notifying bomb), 서버가 입력을 검증해 스코어보드를 갱신하는 구조로 이를 해결한다. 이 기능은 같은 구조를 **SSH 공용 서버** 환경에 맞게 구현한다.

## 2. 목표 (What)

1. 참가자는 대회 서버에 SSH로 접속해 **자기 계정 안에서** 폭탄을 해체한다.
2. 폭발·해제는 발생 즉시 서버 DB에 기록되며, 참가자가 조작하거나 남의 기록을 위조할 수 없다.
3. 웹 리더보드에서 전체 참가자의 진행 상황, 점수, 폭발 기록을 실시간으로 본다.
4. 운영자는 명단 파일 하나로 계정·폭탄을 일괄 준비하고, 명령 몇 개로 대회를 운영한다.

### 성공 기준

- 30명 규모 대회를 서버 1대로 무리 없이 진행한다.
- 참가자는 SSH 접속 정보 카드 한 장만 받으면 바로 시작할 수 있다.
- 대회 종료 즉시 최종 순위가 확정되며, 로그 수거 작업이 없다.

## 3. 사용자 시나리오

### S1. 참가자
접속 정보 카드(서버 주소·ID·비밀번호)를 받는다. 대회 시작 시각이 되면 `ssh bomb07@서버`로 접속한다. `~/bomb/`에서 `objdump`와 `gdb`로 폭탄을 분석하고 `./bomb answers.txt`로 실행한다. 해제하거나 폭발할 때마다 브라우저에 띄워 둔 리더보드에 자기 닉네임의 칸이 바뀐다.

### S2. 운영자 — 준비
Ubuntu 서버에 저장소를 받아 설치 스크립트를 실행한다. 설정 파일에 대회 시각과 채점 규칙을 적는다. 참가자 닉네임 명단 CSV로 계정과 폭탄을 일괄 생성하고, 출력된 접속 정보 카드를 인쇄해 나눠 준다. 계정은 시작 시각 전까지 잠겨 있다.

### S3. 운영자 — 대회 중
설정 시각에 따라 계정 잠금이 풀리고 대회가 시작된다. 관리자 화면에서 모든 참가자의 이벤트와 입력 원문을 실시간으로 본다. 필요하면 명령으로 시작을 늦추거나 종료를 연장한다. 종료 30분 전 공개 리더보드가 고정(프리즈)된다.

### S4. 운영자 — 종료
종료 시각이 되면 새 로그인과 기록이 차단된다. 프리즈를 해제해 최종 순위를 공개하고, 결과를 CSV로 내보낸다.

## 4. 기능 요구사항 (FR)

| ID | 요구사항 |
|---|---|
| FR-01 | 서버 모드 폭탄은 phase 시작 전에 기록 서버에 접속을 확인하고, 실패하거나 대회 시간이 아니면 사유를 알리고 phase를 시작하지 않는다. |
| FR-02 | 폭발과 해제는 발생 즉시 phase 번호와 입력 원문을 포함해 서버에 보고된다. secret phase 포함. |
| FR-03 | 서버는 보고한 프로세스의 **운영체제 사용자**로 참가자를 식별한다. 폭탄 파일이나 메시지 내용으로 신원을 판단하지 않는다. |
| FR-04 | 서버는 해제 보고의 입력을 그 참가자의 정답 규칙으로 **다시 채점**하고, 통과할 때만 해제로 인정한다. 채점에 실패한 해제 보고는 폭발 1회로 계산한다. |
| FR-05 | 서버 응답은 해제 보고의 유효 여부를 드러내지 않는다. |
| FR-06 | 참가자별 보고 빈도를 제한한다(기본 분당 60건). |
| FR-07 | 공개 리더보드는 닉네임·phase별 해제 여부와 시각·폭발 수·점수·순위를 보여주며 자동 갱신된다. |
| FR-08 | 공개 폭발·해제 기록 피드는 닉네임·phase·시각만 보여주고 **입력 원문은 보여주지 않는다**. |
| FR-09 | 프리즈 시각 이후 공개 화면은 프리즈 시점 기준으로 고정되고, 관리자 화면은 계속 실시간으로 갱신된다. |
| FR-10 | 관리자 화면은 인증 후에만 접근 가능하며, 참가자별 전체 이벤트와 입력 원문을 보여준다. |
| FR-11 | 채점 규칙(phase별 점수, secret 점수, 폭발 감점, 감점 상한)은 설정 파일로 정한다. 기본값: phase 각 10점, secret 10점, 폭발 -0.5점, 감점 상한 20점. 동점은 마지막으로 점수가 오른 시각이 빠른 순. |
| FR-12 | 대회 상태(시작 전/진행/프리즈/종료)는 설정 시각으로 자동 전환되며, 운영자 명령으로 언제든 덮어쓸 수 있고 다시 자동으로 되돌릴 수 있다. |
| FR-13 | 종료 이후 도착한 보고는 기록하되 점수에 반영하지 않는다. |
| FR-14 | 명단 CSV 한 번으로 참가자 계정, 무작위 비밀번호, 참가자별 폭탄, 인쇄용 접속 정보 카드를 생성한다. 이미 존재하는 참가자는 건너뛴다. |
| FR-15 | 참가자 계정은 시작 전까지 로그인할 수 없고, 시작 시 자동으로 열리며, 종료 시 새 로그인이 차단된다. |
| FR-16 | 운영자는 비밀번호 재발급, 상태 조회, 최종 결과 내보내기를 명령으로 수행한다. |
| FR-17 | 오프라인 모드(001의 로컬 로그 방식) 빌드는 그대로 유지된다. |

## 5. 비기능 요구사항 (NFR)

| ID | 요구사항 |
|---|---|
| NFR-01 **위조 불가** | 참가자는 다른 참가자 명의로 기록을 남길 수 없고, 정답을 모르는 채 해제 기록을 얻을 수 없다. |
| NFR-02 **정답 비노출** | 참가자 폭탄에는 시드가 들어가지 않는다. 폭탄 생성기 소스, 시드, 기록 DB, 다른 참가자의 파일·프로세스는 참가자 계정에서 읽을 수 없다. |
| NFR-03 **채점 일치** | 서버의 재채점 결과는 폭탄 바이너리의 판정과 경계 입력을 포함해 **항상 일치**한다. 불일치는 억울한 감점이므로 자동 검증으로 차단한다. |
| NFR-04 **자원 공정성** | 참가자 한 명이 CPU·메모리·프로세스를 독점해 다른 참가자를 방해할 수 없다. |
| NFR-05 **가용성** | 기록·웹 서비스는 비정상 종료 시 자동 재시작된다. 기록 서버가 잠시 불통이어도 해제 기록이 유실되지 않는다(폭탄이 해제 보고 실패 시 멈추고 재실행을 안내). |
| NFR-06 **의존성 최소화** | 서버 구성요소는 Ubuntu 기본 패키지와 Python 표준 라이브러리만 사용한다. |
| NFR-07 **이식성** | Ubuntu 22.04와 24.04에서 설치 스크립트 하나로 동작한다. 클라우드 VM과 학교 서버 모두 지원한다. |
| NFR-08 **무권한 검증** | 서버 핵심 동작은 root 권한 없이 로컬(WSL)에서 자동 검증할 수 있다. |

## 6. 수용 기준 (Acceptance Criteria)

- **AC-01** 정답 파일 실행 시 서버 DB에 해제 6건이 기록되고 리더보드 점수가 60점이다.
- **AC-02** secret 정답까지 실행하면 secret 점수가 더해진다.
- **AC-03** 오답으로 폭발하면 폭발 1건이 기록되고 설정된 감점이 적용된다.
- **AC-04** 소켓에 직접 접속해 틀린 입력으로 해제를 주장하면 `invalid`로 기록되어 폭발로 계산되고, 해제 점수는 오르지 않으며, 응답은 정상 기록과 구별되지 않는다.
- **AC-05** 다른 참가자의 폭탄 ID로 보고하면 거부된다.
- **AC-06** 대회 시작 전 폭탄을 실행하면 phase를 시작하지 않고 종료한다.
- **AC-07** 프리즈 이후 이벤트는 공개 API에 반영되지 않고 관리자 API에는 반영된다.
- **AC-08** 종료 이후 이벤트는 점수에 반영되지 않는다.
- **AC-09** 보고 빈도 한도를 넘으면 거부되고 기록된다.
- **AC-10** 인증 없이 관리자 화면에 접근하면 401을 받는다.
- **AC-11** 20개 시드에서 경계 입력 퍼징 결과 서버 채점과 폭탄 판정이 모두 일치한다.
- **AC-12** 참가자 계정에서 다른 참가자 홈, 생성기 저장소, 기록 DB를 읽을 수 없고, 다른 참가자의 프로세스가 보이지 않으며, SSH 포트 포워딩이 거부된다.
- **AC-13** 시작 시각 전 SSH 로그인이 거부되고, 시작 후 허용되며, 종료 후 새 로그인이 거부된다.
- **AC-14** 001의 오프라인 검증(`make verify`)이 계속 통과한다.

AC-01~11, 14는 root 없이 자동 검증한다. AC-12, 13은 실서버 리허설로 검증한다.

## 7. 범위 밖 (Out of Scope)

- 참가자 PC에서의 AI 사용·외부 검색 차단 — 규칙과 감독으로 통제한다.
- 서버의 외부 인터넷 송신 차단 — 운영 결정에 따라 허용한다.
- 다중 서버·로드밸런싱 — 30명 규모에서 불필요하다.
- 웹에서의 참가자 자가 가입.
- gdb로 폭발을 피하는 행위의 차단 — 이 랩의 정석 기법이다.

## 8. 미해결 사항

- 서버 위치(클라우드/학교 서버)와 도메인·HTTPS 여부.
- 채점 기본값: 실제 CMU 과제 안내문은 phase 1~4 각 10점, 5~6 각 15점이다. 설정 파일에 병기하고 운영자가 결정한다.
