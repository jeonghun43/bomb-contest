# x86-64 리버싱 개념 정리

연습 중에도, 나중에 수업 과제를 할 때도 옆에 두고 보는 자료입니다. **이 문서에는 폭탄의 정답이 없습니다.** 어셈블리를 읽을 때 반복해서 마주치는 개념과 패턴만 정리했습니다. 각 패턴은 개념 드릴([DRILLS.md](DRILLS.md))에서 직접 연습할 수 있습니다.

어셈블리는 `objdump`와 gdb의 기본값인 **AT&T 문법**으로 적습니다(`mov 원본, 대상`).

---

## 0. 이 문제를 푸는 기본 자세

폭탄의 각 단계는 결국 이런 모양입니다.

```
입력을 읽는다  →  몇 가지 계산을 한다  →  결과를 어떤 값과 비교한다
                                          같으면 통과, 다르면 폭발
```

그러니 할 일은 **"어떤 계산을 하는가"** 와 **"무엇과 비교하는가"** 를 알아낸 뒤, 그 계산을 거꾸로 되돌리는 것입니다.

무작정 값을 넣어 보지 마세요. 계산을 이해하면 답이 정해집니다. 정답이 여러 개인 단계(switch의 case 여러 개, 하위 4비트만 보는 문자 등)도 있지만, 그것도 구조를 이해하면 바로 보입니다.

---

## 1. x86-64 기초

### 1.1 레지스터

64비트 이름과 하위 32비트 이름은 같은 물리 레지스터입니다.

| 64bit | 32bit | 16bit | 8bit | 흔한 쓰임 |
|---|---|---|---|---|
| `rax` | `eax` | `ax` | `al` | 반환값, 산술 |
| `rbx` | `ebx` | | `bl` | 보존(callee-saved) |
| `rcx` | `ecx` | | `cl` | 4번째 인자, 시프트 횟수 |
| `rdx` | `edx` | | `dl` | 3번째 인자 |
| `rsi` | `esi` | | `sil` | 2번째 인자 |
| `rdi` | `edi` | | `dil` | 1번째 인자 |
| `rsp` | | | | 스택 포인터 |
| `rbp` | `ebp` | | `bpl` | 보존(callee-saved). 최적화된 코드에서는 프레임 포인터가 아님 |
| `r8`~`r15` | `r8d`~ | | | 5·6번째 인자(`r8`, `r9`)와 임시값. `r12`~`r15`는 보존 |

**중요**: `mov %edi,%eax` 처럼 32비트 레지스터에 쓰면 상위 32비트가 **0으로 지워집니다**.

### 1.2 호출 규약 (System V AMD64)

함수 인자는 왼쪽부터 순서대로:

```
rdi, rsi, rdx, rcx, r8, r9      (그 이상은 스택)
```

반환값은 `rax`(또는 `eax`)에 들어옵니다. `f(a, b, c)` 호출은 이렇게 보입니다.

```asm
mov    $0x0,%esi          # 두 번째 인자 = 0
mov    $0xe,%edx          # 세 번째 인자 = 14
mov    0x8(%rsp),%edi     # 첫 번째 인자 = 지역 변수
callq  400fce <func4>
test   %eax,%eax          # 반환값 검사
```

인자를 채우는 순서는 소스 순서와 다를 수 있습니다. **어느 레지스터에 들어가는지**로 몇 번째 인자인지 판단하세요.

**보존(callee-saved) 레지스터** `rbx`, `rbp`, `r12`~`r15`는 함수가 쓰기 전에 `push`하고 끝날 때 `pop`합니다. 함수 호출을 가로질러 살아남아야 하는 값(반복문 카운터, 첫 재귀 호출의 결과 등)이 여기에 담깁니다.

### 1.3 스택 프레임과 sscanf

함수 시작에서 `sub $N,%rsp`로 지역 변수 공간을 확보하고, 끝에서 `add $N,%rsp`로 되돌립니다. 지역 변수는 `0xc(%rsp)` 같은 형태로 접근합니다.

`sscanf`에 넘기는 포인터가 어떤 스택 주소인지 보면, **몇 개의 값을 읽고 각각 어디에 저장하는지** 알 수 있습니다.

```asm
lea    0xc(%rsp),%rcx       # 두 번째 값을 받을 주소
lea    0x8(%rsp),%rdx       # 첫 번째 값을 받을 주소
mov    $0x4025cf,%esi       # 형식 문자열의 주소  → x/s 0x4025cf
mov    $0x0,%eax
callq  <__isoc99_sscanf@plt>
cmp    $0x1,%eax            # 반환값(읽은 개수)과 비교
jg     ...
```

형식 문자열(`"%d %d"`, `"%d %c %d"` …)은 `x/s`로 확인합니다. `sscanf`의 반환값과 비교하는 상수가 **그 줄에 몇 개의 값을 적어야 하는지** 알려 줍니다. 형식에 없는 뒷부분은 무시됩니다(숨은 단계의 열쇠가 여기 있습니다).

## 2. 도구

### 2.1 objdump — 정적 분석

```bash
objdump -d bomb > bomb.asm            # 전체 디스어셈블
objdump -d --no-show-raw-insn bomb    # 기계어 바이트 생략, 읽기 편함
objdump -t bomb                       # 심볼 표 (함수·전역 변수 이름과 주소)
objdump -s -j .rodata bomb            # 읽기 전용 데이터 덤프
strings bomb                          # 문자열 후보 훑어보기
```

먼저 `objdump -t`로 함수 목록을 훑어보세요. 이름이 남아 있으므로 어디를 봐야 할지 바로 알 수 있습니다. `node1`, `n1`, `array.3449` 같은 전역 데이터의 이름과 크기도 여기서 확인합니다.

디스어셈블 결과를 읽을 때는 **분기 대상 주소를 화살표로 이어 그리는 것**이 가장 효과적입니다. 어디로 점프하면 통과이고 어디로 가면 폭발인지 표시해 두면 구조가 한눈에 들어옵니다.

### 2.2 gdb — 동적 분석

```bash
gdb ./bomb
```

| 명령 | 설명 |
|---|---|
| `break <함수명>` / `b *0x400f6a` | 중단점. 주소 앞에는 `*` |
| `run [파일]` / `r` | 실행 |
| `continue` / `c` | 계속 |
| `stepi` / `si` | 명령어 하나 실행 |
| `nexti` / `ni` | 명령어 하나 실행, `call`은 통째로 넘김 |
| `finish` | 현재 함수가 끝날 때까지 (반환값 표시) |
| `disas` | 현재 함수 디스어셈블 |
| `info registers` / `i r` | 전체 레지스터 |
| `p/x $eax`, `p/d $eax`, `p/c 0x6b` | 값 출력 (16진·10진·문자) |
| `x/<개수><형식><단위> <주소>` | 메모리 덤프 |
| `display/i $pc` | 매 정지마다 현재 명령어 표시 |
| `layout asm` | 어셈블리 화면 (TUI) |

**폭발을 막는 방법** — 이 랩의 정석입니다.

```
(gdb) break explode_bomb
(gdb) run answers.txt
```

답이 틀리면 폭발 함수 진입 직전에 멈춥니다. 그 상태에서 `backtrace`로 어디서 걸렸는지, `info registers`로 어떤 값이 비교되었는지 볼 수 있습니다. **새 단계는 반드시 이렇게 먼저 시험하세요.** 서버에 기록되는 폭발은 이 중단점을 걸지 않았을 때뿐입니다.

**답 파일**: `./bomb answers.txt`는 파일의 줄을 다 읽으면 **표준 입력에서 이어서** 읽습니다. 푼 단계까지 파일에 적어 두고 다음 단계만 직접 입력하세요. 빈 줄은 건너뜁니다.

**메모리 덤프 형식**

```
x/s    0x402400      문자열
x/16c  0x4024b0      문자 16개
x/8dw  0x6032d0      10진수 4바이트 워드 8개
x/8gx  0x402470      8바이트 16진수 8개 (포인터·점프 테이블)
x/24wx &node1        4바이트 16진수 24개 (구조체 여러 개)
x/s    $rsi          레지스터가 가리키는 문자열
```

형식 문자: `x`=16진, `d`=10진, `u`=부호없는 10진, `c`=문자, `s`=문자열, `i`=명령어
단위 문자: `b`=1바이트, `h`=2, `w`=4, `g`=8

## 3. 자주 나오는 어셈블리 패턴

### 3.1 비교와 분기

```asm
cmp    $0x5,%eax       # eax - 5 를 계산해 플래그만 갱신
je     <통과>          # 같으면 점프
```

`cmp a, b`는 AT&T 문법에서 **`b - a`** 를 계산합니다. 피연산자 순서에 주의하세요. `jg`는 "b > a"입니다.

| 명령 | 조건 | 부호 |
|---|---|---|
| `je` / `jz` | 같다 / 0이다 | — |
| `jne` / `jnz` | 다르다 | — |
| `jl` `jle` `jg` `jge` | 작다·작거나같다·크다·크거나같다 | **부호 있음** |
| `jb` `jbe` `ja` `jae` | 아래·아래같음·위·위같음 | **부호 없음** |
| `js` / `jns` | 음수다 / 음수가 아니다 | 부호 비트 |

`test %eax,%eax` + `je`는 "eax가 0인가?"를 뜻합니다.
`test $0x1,%al` + `jne`는 "최하위 비트가 1인가(홀수인가)?"입니다.

**범위 검사 관용구**

```asm
mov    (%r13),%eax
sub    $0x1,%eax
cmp    $0x5,%eax
jbe    <통과>
```

부호 없는 비교에서는 음수가 아주 큰 값이 되므로, 하한을 뺀 뒤 한 번 비교하면 위아래를 동시에 검사합니다. 위 네 줄은 `1 <= x <= 6` 입니다. `cmpl $0x7,0x8(%rsp)` + `ja <폭발>`은 `0 <= x <= 7`입니다.

### 3.2 산술과 lea

`lea`는 **메모리를 읽지 않습니다.** 주소 계산 회로를 빌려 쓰는 덧셈·곱셈입니다.

```asm
lea    (%rax,%rax,2),%eax      # eax = rax*3
lea    0x1(%rax,%rax,1),%eax   # eax = rax*2 + 1
lea    -0x2(%rdi),%edi         # edi = rdi - 2
```

| 명령 | 의미 |
|---|---|
| `shl` / `sal` | 왼쪽 시프트 (×2ⁿ) |
| `shr` | 오른쪽 논리 시프트 (0 채움) |
| `sar` | 오른쪽 산술 시프트 (부호 채움) |
| `and $0xf,%eax` | 하위 4비트만 남김 (0~15) |
| `movzbl` / `movsbl` | 1바이트를 0으로 / 부호로 확장해 읽기 |
| `cltq`, `movslq` | 32비트 값을 64비트로 부호 확장 (배열 인덱스 앞에 자주 나옴) |

**음수 나눗셈 보정**: `x / 2`는 이렇게 컴파일됩니다.

```asm
mov    %eax,%ecx
shr    $0x1f,%ecx        # 음수면 1, 아니면 0
add    %ecx,%eax         # 음수면 1을 더해서
sar    %eax              # 0 쪽으로 반올림한 몫
```

### 3.3 곱셈으로 위장한 나눗셈

컴파일러는 **상수로 나누는 나눗셈과 나머지를 나눗셈 명령 없이** 구현합니다. 미리 계산해 둔 큰 상수(magic number)를 곱하고 오른쪽으로 밉니다.

```asm
mov    $0x92492493,%edx      # 정체불명의 큰 상수
mov    %ecx,%eax
imul   %edx                  # 64비트 곱셈, 상위 32비트가 edx로
add    %ecx,%edx
sar    $0x2,%edx             # → 여기까지가 몫
mov    %ecx,%eax
sar    $0x1f,%eax
sub    %eax,%edx
lea    0x0(,%rdx,8),%eax     # 몫 × 8
sub    %edx,%eax             # 몫 × 7
sub    %eax,%ecx             # 원래 값 - 몫×7 = 나머지
```

**핵심**: 나머지를 구하려면 **몫 × 나누는 수**를 빼야 합니다. 그 곱셈(`imul $상수`, 또는 위처럼 `lea`·`shl` 조합)이 나누는 수를 드러냅니다. 앞부분의 괴상한 곱셈은 몫을 구하는 과정일 뿐, 손으로 따라 계산할 필요가 없습니다.

### 3.4 배열과 구조체

`(base, index, scale)` 에서 **scale이 원소 크기**입니다.

| scale | 원소 크기 | 대표 타입 |
|---|---|---|
| 1 | 1바이트 | `char` |
| 4 | 4바이트 | `int` |
| 8 | 8바이트 | `long`, **포인터** |

```asm
mov    (%rsp,%rbx,4),%eax      # int 배열 a[rbx]
movzbl 0x4024b0(%rdx),%edx     # 전역 char 배열[rdx]
mov    0x402470(,%rax,8),%rdx  # 8바이트 칸 = 포인터 배열
```

배열에 든 것이 **값인지 포인터인지** 구분하세요. 포인터 배열은 `x/8gx`로 주소를 보고, 각 주소를 다시 `x/s`나 `x/4wx`로 따라갑니다.

**구조체 필드**는 고정된 오프셋으로 접근합니다.

```asm
mov    (%rbx),%eax         # +0  첫 번째 필드 (int)
mov    0x8(%rbx),%rbx      # +8  포인터 필드 (next, left 등)
mov    0x10(%rbx),%rdi     # +16 또 다른 포인터 (right 등)
```

`int` 다음에 포인터가 오면 정렬 때문에 4바이트 여백이 생깁니다. `{int value; int index; node *next;}`는 16바이트, `{int value; node *left, *right;}`는 24바이트입니다.

**연결 리스트 순회**

```asm
loop:
  mov    0x8(%rdx),%rdx     # p = p->next
  add    $0x1,%eax
  cmp    %ecx,%eax
  jne    loop
```

`x/24wx &node1`로 노드 여섯 개를 한 번에 보고, next 필드(+8)의 주소가 어느 노드인지 맞춰 가며 그림을 그리세요.

### 3.5 switch와 점프 테이블

case가 0, 1, 2 … 처럼 촘촘하면 컴파일러는 **점프 테이블**을 만듭니다.

```asm
cmpl   $0x7,0x8(%rsp)       # 범위 검사 (ja: 음수도 걸러짐)
ja     <default>
mov    0x8(%rsp),%eax
jmpq   *0x402470(,%rax,8)   # 테이블[index] 주소로 점프
```

`x/8gx 0x402470`로 테이블을 보면 case마다 시작 주소가 나옵니다. 그 주소로 가서 `mov $값,%eax` 같은 상수를 읽습니다.

- case가 0이 아닌 수부터 시작하면 먼저 `sub $시작값,%eax`를 하고 범위를 검사합니다.
- case 값이 띄엄띄엄이면 테이블 대신 `cmp`/`je`/`jg`가 줄줄이 나오는 **비교 트리**가 됩니다.
- `break`가 없는 case는 다음 case의 코드로 그대로 흘러갑니다(fall-through).

### 3.6 재귀 함수 읽기

1. **종료 조건**을 찾는다 (`test %rdi,%rdi` / `je`, `cmp $0x1,%edi` / `jle` …).
2. **재귀 호출의 인자**를 적는다 (`lea -0x1(%rdi),%edi` = n-1, `lea 0x1(%rcx),%esi` = mid+1 …).
3. **돌아온 값을 어떻게 쓰는지** 본다 (`add %eax,%eax` = ×2, `lea 0x1(%rax,%rax,1),%eax` = ×2+1, `add %ebp,%eax` = 앞 결과와 합산).

그다음 작은 입력으로 호출 트리를 손으로 그려 보세요. gdb에서는 `break <함수>` 후 매번 `info registers rdi rsi rdx`, 돌아올 때 `finish`로 반환값을 봅니다.

### 3.7 스택 카나리

```asm
mov    %fs:0x28,%rax
mov    %rax,0x18(%rsp)
xor    %eax,%eax
...
mov    0x18(%rsp),%rax
xor    %fs:0x28,%rax
je     <정상 종료>
callq  <__stack_chk_fail@plt>
```

스택에 문자 배열이 있는 함수에 컴파일러가 넣는 **버퍼 오버플로 감시 장치**입니다. 문제 풀이와는 상관없으니 이 줄들은 건너뛰고 읽으세요. 카나리가 있다는 것은 "이 함수 스택에 문자 배열이 있다"는 힌트이기도 합니다.

### 3.8 리틀 엔디언

x86-64는 **낮은 바이트를 낮은 주소에** 저장합니다.

```asm
movabs $0x6766656463626261,%rax
mov    %rax,(%rsp)
```

메모리에는 `61 62 62 63 64 65 66 67` = `"abbcdefg"` 순서로 놓입니다. 지역 문자열이 즉시값으로 조립될 때, 그리고 `x/2wx`와 `x/8xb`의 출력 순서가 달라 보일 때 이 점을 떠올리세요.

## 4. 거꾸로 푸는 도구 상자

| 앞으로 가는 연산 | 되돌리는 방법 |
|---|---|
| `x + k` / `x - k` | 빼기 / 더하기 |
| `x ^ k` | 같은 `k`로 다시 XOR |
| `a*x + b = c` | `x = (c - b) / a` |
| 몫 `x / d == q`, 나머지 `x % d == r` | `x = q*d + r` |
| "15에 도착할 때까지 next를 따라간다" | 15에서 거꾸로: `next[j] == 15`인 j, 그 앞 … |
| 재귀 반환값 = 경로의 비트 | 반환값을 2진수로 쓰고 아래 비트부터 읽기 |
| 점화식 `a[i] = f(a[i-1])` | 시작값 하나만 찾으면 나머지는 앞으로 계산 |

값의 개수가 작으면(노드 6개, case 8개, 표 16칸) **전부 표로 그려 놓고 조건에 맞는 것을 고르는 편**이 계산보다 빠릅니다.

## 5. 작업 순서 제안

1. `objdump -t bomb`로 함수와 전역 변수 목록 확보
2. 관심 함수를 `objdump -d`로 뽑아 파일에 저장
3. `sscanf` 형식 문자열과 반환값 비교로 **입력 개수와 형식** 파악
4. 폭발로 가는 분기를 전부 표시 → **통과 조건들의 목록** 작성
5. 조건에 등장하는 상수와 전역 데이터를 gdb로 덤프
6. 조건을 C 의사코드로 옮겨 적기
7. 종이에서 역산
8. gdb에서 `break explode_bomb` 을 걸고 답 시험 → 답 파일에 추가

## 6. 자주 막히는 지점

**"상수가 안 보인다"** — 즉시값이 주소일 수 있습니다(`mov $0x402400,%esi`). gdb에서 `x/s`, `x/8gx` 등으로 그 주소를 보세요.

**"비교 대상이 레지스터라서 값을 모르겠다"** — 정적으로 못 읽으면 동적으로 보면 됩니다. 그 `cmp` 주소에 중단점을 걸고 `info registers`.

**"루프가 뭘 하는지 모르겠다"** — 한 바퀴만 `si`로 따라가며 레지스터를 기록하세요. 두 바퀴째면 대개 패턴이 보입니다.

**"함수가 너무 길다"** — 덩어리로 나누세요. 범위 검사 / 변환 / 자료 구조 만들기 / 최종 검사처럼 루프 단위로 끊어 읽으면 각각은 짧습니다.

**"큰 상수와의 곱셈이 뭔지 모르겠다"** — 3.3절. 나눗셈입니다.

**"숨은 단계가 있다는데 어디서 시작하지?"** — `phase_defused`를 읽으세요. 어떤 조건에서 `secret_phase`를 부르는지가 전부 거기 있습니다.
