# x86-64 리버싱 개념 정리

대회 중 자유롭게 참고하는 자료입니다. **이 문서에는 폭탄의 정답이나 특정 단계에 대한 정보가 전혀 없습니다.** 어셈블리를 읽을 때 반복해서 마주치는 큰 개념들만 정리했습니다.

---

## 0. 이 문제를 푸는 기본 자세

폭탄의 각 단계는 결국 이런 모양입니다.

```
입력을 읽는다  →  몇 가지 계산을 한다  →  결과를 어떤 값과 비교한다
                                          같으면 통과, 다르면 폭발
```

그러니 여러분이 할 일은 **"어떤 계산을 하는가"** 와 **"무엇과 비교하는가"** 를 알아낸 뒤, 그 계산을 거꾸로 되돌리는 것입니다.

무작정 값을 넣어 보지 마세요. 계산을 이해하면 답은 하나로 결정됩니다. **모든 단계는 종이와 펜으로 역산할 수 있게 만들어져 있습니다.** 경우의 수를 수십 개씩 시도해야 하는 단계는 없습니다. 그런 상황이 되었다면 문제를 잘못 읽고 있는 것입니다.

---

## 1. x86-64 기초

### 1.1 레지스터

64비트 이름과 하위 32비트 이름은 같은 물리 레지스터입니다.

| 64bit | 32bit | 16bit | 8bit | 흔한 쓰임 |
|---|---|---|---|---|
| `rax` | `eax` | `ax` | `al` | 반환값, 산술 |
| `rbx` | `ebx` | | `bl` | 보존 레지스터 |
| `rcx` | `ecx` | | `cl` | 4번째 인자, 시프트 횟수 |
| `rdx` | `edx` | | `dl` | 3번째 인자 |
| `rsi` | `esi` | | `sil` | 2번째 인자 |
| `rdi` | `edi` | | `dil` | 1번째 인자 |
| `rsp` | | | | 스택 포인터 |
| `rbp` | | | | 프레임 포인터 (최적화되면 안 쓰일 수 있음) |
| `r8`~`r15` | `r8d`~ | | | 5·6번째 인자와 임시값 |

**중요**: `mov %edi, %eax` 처럼 32비트 레지스터에 쓰면 상위 32비트가 **0으로 지워집니다**.

### 1.2 호출 규약 (System V AMD64)

함수 인자는 왼쪽부터 순서대로:

```
rdi, rsi, rdx, rcx, r8, r9      (그 이상은 스택)
```

반환값은 `rax`(또는 `eax`)에 들어옵니다.

`f(a, b)`를 호출하는 코드는 이렇게 보입니다.

```asm
mov    $0x5, %esi        ; 두 번째 인자 b = 5
mov    %ebx, %edi        ; 첫 번째 인자 a = ebx
call   401cf1 <f>
; 결과는 eax
```

### 1.3 스택 프레임

함수 시작에서 `sub $N, %rsp`로 지역 변수 공간을 확보하고, 끝에서 `add $N, %rsp`로 되돌립니다. 지역 변수는 `-0x4(%rbp)` 또는 `0xc(%rsp)` 같은 형태로 접근합니다.

`sscanf`에 넘기는 포인터가 어떤 스택 주소인지 보면, **몇 개의 값을 읽고 각각 어디에 저장하는지** 알 수 있습니다.

```asm
lea    0x8(%rsp), %rcx      ; 두 번째 정수를 받을 주소
lea    0xc(%rsp), %rdx      ; 첫 번째 정수를 받을 주소
lea    0xd35(%rip), %rsi    ; 포맷 문자열
call   __isoc99_sscanf
cmp    $0x2, %eax           ; 두 개를 제대로 읽었는가?
```

`sscanf`의 반환값과 비교하는 상수가 **그 줄에 몇 개의 값을 적어야 하는지** 알려 줍니다.

## 2. 도구

### 2.1 objdump — 정적 분석

```bash
objdump -d bomb > bomb.asm            # 전체 디스어셈블
objdump -d --no-show-raw-insn bomb    # 기계어 바이트 생략, 읽기 편함
objdump -d -M intel bomb              # Intel 문법 (mov dst, src)
objdump -t bomb                       # 심볼 표 (함수·전역 변수 이름과 주소)
objdump -s -j .rodata bomb            # 읽기 전용 데이터 덤프
```

먼저 `objdump -t`로 함수 목록을 훑어보세요. 이름이 남아 있으므로 어디를 봐야 할지 바로 알 수 있습니다. 전역 배열의 심볼 이름과 크기도 여기서 확인합니다.

디스어셈블 결과를 읽을 때는 **분기 대상 주소를 화살표로 이어 그리는 것**이 가장 효과적입니다. 어디로 점프하면 통과이고 어디로 가면 폭발인지 표시해 두면 구조가 한눈에 들어옵니다.

### 2.2 gdb — 동적 분석

```bash
gdb ./bomb
```

| 명령 | 설명 |
|---|---|
| `break <함수명>` / `b *0x401440` | 중단점. 주소 앞에는 `*` |
| `run [파일]` / `r` | 실행 |
| `continue` / `c` | 계속 |
| `stepi` / `si` | 명령어 하나 실행 |
| `nexti` / `ni` | 명령어 하나 실행, `call`은 통째로 넘김 |
| `finish` | 현재 함수가 끝날 때까지 |
| `disas` | 현재 함수 디스어셈블 |
| `info registers` / `i r` | 전체 레지스터 |
| `p/x $eax` | eax를 16진수로 출력 |
| `x/<개수><형식><단위> <주소>` | 메모리 덤프 |
| `set $eax = 5` | 레지스터 값 바꾸기 |
| `layout asm` | 어셈블리 화면 (TUI) |

**폭발을 막는 방법** — 이 랩의 정석입니다.

```
(gdb) break explode_bomb
(gdb) run answers.txt
```

답이 틀리면 폭발 함수 진입 직전에 멈춥니다. 그 상태에서 `backtrace`로 어디서 걸렸는지, `info registers`로 어떤 값이 비교되었는지 볼 수 있습니다.

**메모리 덤프 형식**

```
x/16xb &배열이름     16개를 16진수 바이트로
x/8xw  &배열이름     8개를 16진수 4바이트 워드로
x/8dw  &배열이름     10진수 워드로
x/s    $rdi          문자열로
x/4gx  $rsp          8바이트 단위 16진수
```

형식 문자: `x`=16진, `d`=10진, `u`=부호없는 10진, `c`=문자, `s`=문자열, `i`=명령어
단위 문자: `b`=1바이트, `h`=2, `w`=4, `g`=8

## 3. 자주 나오는 어셈블리 패턴

### 3.1 비교와 분기

```asm
cmp    $0x5, %eax      ; eax - 5 를 계산해 플래그만 갱신
je     <통과>          ; 같으면 점프
```

`cmp a, b`는 AT&T 문법에서 **`b - a`** 를 계산합니다. 피연산자 순서에 주의하세요.

| 명령 | 조건 | 부호 |
|---|---|---|
| `je` / `jz` | 같다 / 0이다 | — |
| `jne` / `jnz` | 다르다 | — |
| `jl` `jle` `jg` `jge` | 작다·작거나같다·크다·크거나같다 | **부호 있음** |
| `jb` `jbe` `ja` `jae` | 아래·아래같음·위·위같음 | **부호 없음** |

`test %eax, %eax` + `je`는 "eax가 0인가?"를 뜻합니다.
`test $0x1, %al` + `jne`는 "최하위 비트가 1인가?"입니다.

**범위 검사 관용구** — 이 패턴을 알아두면 유용합니다.

```asm
sub    $0x1, %eax
cmp    $0x563, %eax
ja     <폭발>
```

`ja`는 부호 **없는** 비교입니다. 값에서 하한을 뺀 뒤 부호 없는 비교를 하면, 음수는 아주 큰 값이 되어 한 번에 걸립니다. 즉 위 세 줄은 `1 <= 원래값 <= 0x564` 를 뜻합니다.

값 **두 개**를 한꺼번에 검사할 때는 OR로 합치기도 합니다.

```asm
mov    0xc(%rsp), %eax
or     0x8(%rsp), %eax
cmp    $0x3, %eax
jbe    <통과>
```

두 값을 OR한 결과가 3 이하라는 것은, 둘 다 0~3 범위이고 음수도 아니라는 뜻입니다(음수면 상위 비트가 켜져 값이 커집니다). 즉 `0 <= a <= 3 && 0 <= b <= 3` 을 네 줄로 줄인 것입니다.

### 3.2 비트 연산

| 명령 | 의미 |
|---|---|
| `and`, `or`, `xor`, `not` | 비트 논리 연산 |
| `shl` / `sal` | 왼쪽 시프트 (×2ⁿ) |
| `shr` | 오른쪽 논리 시프트 (0 채움, 부호 없음) |
| `sar` | 오른쪽 산술 시프트 (부호 비트 채움) |
| `rol` / `ror` | 회전. 밀려난 비트가 반대쪽으로 들어옴 |

**회전은 되돌릴 수 있습니다.** `rol n` 의 역은 `ror n`, `ror n` 의 역은 `rol n` 입니다.
**XOR도 되돌릴 수 있습니다.** `x ^ k ^ k == x` 입니다.

C에서 `(v << n) | (v >> (32-n))` 이라고 쓰면 컴파일러가 `rol` 한 줄로 바꿉니다. 반대로 어셈블리에서 `rol`을 보면 소스에는 시프트 두 개와 OR가 있었다고 읽으면 됩니다.

**비트를 세는 루프**

```asm
loop:
  mov  %eax, %edx
  and  $0x1, %edx
  add  %edx, %ecx
  shr  %eax
  test %eax, %eax
  jne  loop
```

최하위 비트를 더하고 오른쪽으로 미는 것을 반복 → **1인 비트의 개수(popcount)** 를 세는 코드입니다.

**비트를 뒤집는 루프**

```asm
loop:
  add  %edx, %edx        ; 결과를 왼쪽으로 밀고
  mov  %eax, %ecx
  and  $0x1, %ecx
  or   %ecx, %edx        ; 입력의 현재 최하위 비트를 넣고
  shr  %eax              ; 입력을 오른쪽으로 민다
```

한쪽에서 빼서 다른 쪽에 쌓는 모양이면 **비트 순서를 뒤집는** 코드입니다.

**부분집합 검사**

```asm
mov   %eax, %ecx
and   %ebx, %ecx
cmp   %eax, %ecx
jne   <폭발>
```

`(a & b) == a` 는 "a의 1비트가 모두 b에도 있다", 즉 **a가 b의 부분집합**이라는 뜻입니다. 마스크를 다루는 코드에서 자주 보입니다.

### 3.3 곱셈으로 위장한 나눗셈 — 반드시 알아 둘 것

컴파일러는 **상수로 나누는 나눗셈과 나머지 연산을 나눗셈 명령 없이** 구현합니다. `div`/`idiv`가 느리기 때문에, 미리 계산해 둔 큰 상수(magic number)를 곱하고 오른쪽으로 미는 방식으로 바꿉니다.

전형적인 모양입니다.

```asm
movslq %edx, %rax
imul   $0xffffffffbdd265f5, %rax, %rax   ; 정체불명의 큰 상수와 곱셈
shr    $0x20, %rax                       ; 상위 32비트만 취함
add    %edx, %eax
sar    $0xa, %eax                        ; 오른쪽으로 밀기  → 여기까지가 몫
mov    %edx, %ecx
sar    $0x1f, %ecx                       ; 부호 보정
sub    %ecx, %eax
imul   $0x565, %eax, %eax                ; 몫 × 제수
sub    %eax, %edx                        ; 원래 값 - (몫 × 제수) = 나머지
```

**핵심**: 마지막의 `imul $상수` 와 `sub` 조합이 보이면, 그 `$상수`가 바로 **나누는 수**입니다. 그리고 그 결과는 **나머지**입니다. 앞부분의 괴상한 곱셈과 시프트는 몫을 구하는 과정일 뿐, 손으로 따라 계산할 필요가 없습니다.

위 코드는 그냥 이렇게 읽으면 됩니다.

```c
result = value % 0x565;      /* 0x565 = 1381 */
```

### 3.4 배열과 구조체 접근

`lea`는 계산만 하고 메모리를 읽지 않습니다. 주소 계산이나 산술 트릭에 쓰입니다.

```asm
lea    (%rdi,%rsi,4), %rax     ; rax = rdi + rsi*4      → int 배열의 [rsi]번 원소 주소
mov    (%rax), %eax            ; 그 값을 읽음
```

`(base, index, scale)` 에서 **scale이 원소 크기**입니다.

| scale | 원소 크기 | 대표 타입 |
|---|---|---|
| 1 | 1바이트 | `char`, `unsigned char` |
| 2 | 2바이트 | `short` |
| 4 | 4바이트 | `int`, `unsigned` |
| 8 | 8바이트 | `long`, 포인터 |

**2차원 배열**은 1차원으로 펼쳐집니다. `grid[r][c]` (열 개수 N)는 `grid + r*N + c` 로 계산되므로, `imul`이나 `shl`로 행 번호에 N을 곱하는 코드가 먼저 나옵니다.

**구조체 필드**는 고정된 오프셋으로 접근합니다.

```asm
mov    0x0(%rax), %edx     ; 첫 번째 필드
mov    0x4(%rax), %ecx     ; 두 번째 필드
mov    0x8(%rax), %rax     ; 세 번째 필드 (8바이트 → 포인터일 가능성)
```

**연결 리스트 순회**는 이렇게 보입니다.

```asm
loop:
  ...
  mov    0x8(%rax), %rax    ; node = node->next
  test   %rax, %rax
  jne    loop               ; NULL이 아니면 계속
```

포인터를 따라가려면 gdb에서 한 칸씩 읽으면 됩니다.

```
(gdb) x/4xw 0x404060        ; 노드 하나의 필드들
(gdb) x/4xw <next 주소>     ; 다음 노드
```

**힙 순서 이진 트리**는 배열 하나로 표현되는 트리입니다. 인덱스 `i`의 자식은 `2i+1`(왼쪽), `2i+2`(오른쪽)입니다. 어셈블리에서 `lea (%rax,%rax,1), %edx` (즉 `×2`) 뒤에 `add $1` 이 나오면 이 공식일 가능성이 높습니다.

## 4. 되돌리기 도구 상자

| 앞으로 가는 연산 | 되돌리는 방법 |
|---|---|
| `x ^ k` | 같은 `k`로 다시 XOR |
| `rotl(x, n)` | `rotr(x, n)` |
| `x + k` | `x - k` |
| `x * k` (k가 홀수, 32비트) | `k`의 32비트 곱셈 역원을 곱함 |
| 비트 뒤집기 | 한 번 더 뒤집기 |
| `(x * a) mod p` (p 소수, a≠0) | `a`의 역원을 곱함 — 아래 참고 |

### 4.1 확장 유클리드 — 모듈러 역원 손으로 구하기

`a·x ≡ b (mod p)` 에서 `p`가 소수이고 `a`가 `p`의 배수가 아니면, **해가 정확히 하나** 있습니다. 구하는 법:

1. `gcd(a, p)`를 유클리드 호제법으로 계산하면서 몫을 기록합니다.
2. 거꾸로 올라가며 `a·u + p·v = 1` 이 되는 `u`를 찾습니다.
3. 그 `u`가 `a`의 역원입니다. 답은 `x = b·u mod p`.

예: `a = 7`, `p = 26` 일 때

```
26 = 3·7 + 5
 7 = 1·5 + 2
 5 = 2·2 + 1        ← 나머지 1 도달

되짚어 올라가면
 1 = 5 - 2·2
   = 5 - 2·(7 - 1·5)      = 3·5 - 2·7
   = 3·(26 - 3·7) - 2·7   = 3·26 - 11·7

따라서  -11·7 ≡ 1 (mod 26)  →  7의 역원은 -11 ≡ 15 (mod 26)
검산: 7 × 15 = 105 = 4×26 + 1  ✓
```

숫자가 천 단위여도 표를 그리며 대여섯 줄이면 끝납니다.

### 4.2 선형 점화식 되짚기

`aᵢ₊₁ = f(aᵢ)` 꼴이면 첫 값 하나만 알면 나머지는 순서대로 계산됩니다. 되돌릴 필요조차 없습니다. **비교 대상 상수 중 어느 것이 시작값인지** 찾는 것이 관건입니다.

### 4.3 계산이 아니라 관찰로 푸는 경우

값의 개수가 작으면(예: 좌표 16칸, 노드 6개) **전부 표로 그려 놓고 조건에 맞는 것을 고르는 편**이 계산보다 빠릅니다. 종이에 격자나 화살표를 그리세요. 손으로 몇 줄 적으면 구조가 드러납니다.

## 5. 작업 순서 제안

1. `objdump -t bomb`로 함수와 전역 변수 목록 확보
2. 관심 함수를 `objdump -d`로 뽑아 파일에 저장, 인쇄하거나 에디터에 열기
3. `sscanf` 포맷 문자열과 반환값 비교로 **입력 개수와 형식** 파악
4. 폭발로 가는 분기를 전부 표시 → **통과 조건들의 목록** 작성
5. 조건에 등장하는 상수를 적어 두고, 전역 배열이 있으면 gdb로 덤프
6. 조건을 C 의사코드로 옮겨 적기
7. 종이에서 역산
8. gdb에서 `break explode_bomb` 을 걸고 답 시험

## 6. 자주 막히는 지점

**"상수가 안 보인다"** — `.rodata`에 있을 수 있습니다. `objdump -t`로 심볼 주소를 찾고 gdb에서 `x`로 덤프하세요.

**"비교 대상이 레지스터라서 값을 모르겠다"** — 정적으로 못 읽으면 동적으로 보면 됩니다. 그 `cmp` 주소에 중단점을 걸고 `info registers`.

**"루프가 뭘 하는지 모르겠다"** — 한 바퀴만 `si`로 따라가며 레지스터를 기록하세요. 두 바퀴째면 대개 패턴이 보입니다.

**"경우의 수가 너무 많다"** — 잘못 읽은 것입니다. 모든 단계는 역산으로 풀리게 설계되어 있습니다. 조건 중 하나를 놓쳤거나, 값이 결정되는 지점을 지나쳤을 가능성이 높습니다. 조건 목록을 처음부터 다시 정리해 보세요.

**"큰 상수와의 곱셈이 뭔지 모르겠다"** — 3.3절을 다시 보세요. 나눗셈입니다.
